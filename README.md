# NBA Play-by-Play & Shot Detail Analysis (PySpark)

Big Data & AI midterm project: ingestion, exploratory analysis, and a shot-outcome prediction
baseline built on NBA/WNBA play-by-play and shot-detail data (1996-2024) using Apache Spark
(PySpark) and Spark MLlib.

## Dataset

Source: [NBA Play-by-Play and Shot Details Data 1996-2021 (Kaggle, user `brains14482`)](https://www.kaggle.com/datasets/brains14482/nba-playbyplay-and-shotdetails-data-19962021/data).

`dataset/` contains 486 raw CSV files following the pattern `{family}_{year}.csv` (regular season)
or `{family}_po_{year}.csv` (playoffs). 13 families are present:

- NBA: `cdnnba`, `datanba`, `matchups`, `nbastats`, `nbastatsv3`, `pbpstats`, `shotdetail`
- WNBA: `wnba_cdnnba`, `wnba_datanba`, `wnba_nbastats`, `wnba_nbastatsv3`, `wnba_pbpstats`, `wnba_shotdetail`

This project's analysis (notebooks 02-03) focuses on **`nbastats`** (play-by-play) and
**`shotdetail`** (shot detail), NBA only, since those two have a schema that is consistent across
every season (see notebook 01's findings) and are the most directly relevant to shot-outcome
analysis.

**License/usage:** the dataset is distributed under the terms set on its Kaggle page — check the
page linked above for the current license before any use outside this coursework. It is used here
strictly for academic purposes (Big Data & AI course midterm project); the raw files are not

## Setup

Requires **Python 3.12** (PySpark 3.5.x does not yet support Python 3.13+) and a **JDK/JRE 8, 11,
or 17** — see the environment notes below for why newer Java versions don't work.

```bash
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

Dependencies (see `requirements.txt`): PySpark, pandas, matplotlib, seaborn, jupyter, pyarrow.

## Environment notes (read before running — these caused real failures during development)

Running PySpark locally on Windows surfaced three environment issues that aren't obvious from the
error messages alone. Documenting them here so a fresh setup doesn't hit the same wall:

1. **Java version.** Spark 3.5.x's bundled Hadoop client does not work with Java 21+ (it calls a
   `javax.security.auth.Subject` API that newer JDKs restrict), and will fail at `SparkContext`
   startup with `UnsupportedOperationException: getSubject is supported only if a security manager
   is allowed`. Use a JDK/JRE **8, 11, or 17** instead — the notebooks default to
   `C:\Program Files\Java\jre-1.8`, adjust if yours lives elsewhere.

2. **`winutils.exe` / `hadoop.dll` (Windows only).** Even in local mode, Spark's Hadoop layer shells
   out to `winutils.exe` for local filesystem operations during `.write()` (e.g. Parquet output).
   Without it you'll hit `java.io.FileNotFoundException: HADOOP_HOME and hadoop.home.dir are
   unset`. Download `winutils.exe` and `hadoop.dll` matching the bundled Hadoop version (3.3.x) —
   available from the community-maintained `cdarlint/winutils` GitHub repository — and place them
   at `C:\hadoop\bin\winutils.exe` / `C:\hadoop\bin\hadoop.dll`. The notebooks set `HADOOP_HOME`
   and `PATH` themselves, pointing at `C:\hadoop` by default.

3. **Driver memory must be set before the JVM starts.** Calling
   `SparkSession.builder.config("spark.driver.memory", "...")` has **no effect** in local mode,
   because by the time that Python code runs, the JVM gateway is already up — the setting is
   silently ignored and you'll get `OutOfMemoryError: Java heap space` on anything beyond trivial
   data sizes. Instead, set the environment variable `PYSPARK_SUBMIT_ARGS` (e.g.
   `"--driver-memory 12g pyspark-shell"`) *before* importing `pyspark`/creating the `SparkSession`.
   All three notebooks already do this in their setup cell — if you copy code out of them into a
   plain script, keep this ordering.

If you're on Linux/macOS, point 1 still applies (install a compatible JDK) but points 2-3 regarding
`winutils`/`HADOOP_HOME` are Windows-only; driver memory via `PYSPARK_SUBMIT_ARGS` still applies
everywhere.

## Running the notebooks

Run in order — each one depends on Parquet output from the previous step:

```bash
.venv\Scripts\jupyter nbconvert --to notebook --execute --inplace notebooks/01_schema_inspection_ingestion.ipynb
.venv\Scripts\jupyter nbconvert --to notebook --execute --inplace notebooks/02_eda_and_pyspark_operations.ipynb
.venv\Scripts\jupyter nbconvert --to notebook --execute --inplace notebooks/03_preprocessing_and_ml_baseline.ipynb
```

Or open them interactively with `.venv\Scripts\jupyter notebook`.

| Notebook | Produces |
|---|---|
| **01** — schema inspection & ingestion | Scans all 486 raw CSVs, groups by family, inspects schema per family, ingests each family into one Spark DataFrame (union across years, tagged with `season`/`game_type`), runs a null/row-count sanity check, and saves every family to `output/parquet/{family}/`. |
| **02** — EDA & PySpark operations | Joins `nbastats` + `shotdetail` on a verified composite key, computes FG% by team/season, a cumulative shot-accuracy window function per player, clutch-time shot performance, 3PT attempt rate trends, answers 2 questions in pure Spark SQL, produces 4 visualizations, and runs 4 data quality checks (null rates, duplicates, join integrity, range validity). |
| **03** — preprocessing & ML baseline | Rebuilds the cleaned join from notebook 02, deduplicates and drops orphan/null rows, builds a final modeling table (`output/parquet/modeling_table/`), and trains a Logistic Regression baseline (StringIndexer + OneHotEncoder + VectorAssembler) to predict `SHOT_MADE_FLAG`, evaluated under both a random 80/20 split and a temporal holdout (train ≤2014, test ≥2015) to check for concept drift. |

The raw dataset is ~13GB, so notebook 01's full run (schema inspection + ingestion + sanity check +
Parquet write across all 13 families) takes a while — give it room (development runs used a 1 hour
`nbconvert` timeout and 12GB of driver memory).

## Summary of key results

(Full figures and tables are in `reports/` and `output/`; see the written report for complete
discussion and limitations.)

- `shotdetail` and `nbastats` are the only two of the 13 ingested families with a schema that's
  fully consistent across every season (1996-2024) — 6 of the other families (e.g. `cdnnba`,
  `datanba`, `nbastatsv3`) have genuinely different columns in different seasons.
- League-wide 3-point attempt rate roughly doubled from the late 1990s/2000s (~24-33% for the
  season leader) to 2020-2024 (~46-53%); Restricted Area is the single highest-FG% shot zone in
  **every** season from 1996 to 2024 without exception.
- A Logistic Regression baseline on shot location/distance/timing features beats a naive
  majority-class baseline by ~7-9 accuracy points (AUC ≈ 0.62) but shows **no evidence of concept
  drift** between a random split and a pre-/post-2015 temporal holdout — the geometry of shot
  difficulty is stable even though shot *selection* shifted substantially over the same period.
